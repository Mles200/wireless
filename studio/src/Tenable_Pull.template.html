Tenable PullFetches the Security Center / Nessus exports for the Tenable Report Studio, straight from the API

What this is one minute to read before the first pull

Two files, one job each. Tenable Pull (this page) only fetches: it asks Tenable for the data and gives you the two CSV files the Studio reads, replacing the manual export from Security Center. The Tenable Report Studio makes the report (Excel workbooks, PDF, HTML report, Validate fixes, risk register). The Studio has this same pull built in under its Tenable button, so for the weekly report you only need the Studio; use this page when you want the CSV files on their own, to archive them, send them, or pull on one computer and report on another.
1. KeysCreate API keys for a read-only service account in Security Center (Users › the user › Generate API Keys).
2. ConnectEnter the console address and the keys, click Check connection: it tells you what answered (product, version, user, repositories).
3. PullClick Pull. One request at a time, paced; the result shows the row counts and the load on the server.
4. Report"Open the Studio and load these files", or download the CSVs and drop them on the Studio.

Connection and pull nothing leaves this computer except the requests to the Tenable endpoint

Set-up and troubleshooting

API keys (service account)

  1. Security Center: a user with a read-only role that can see every repository in scope (the built-in Auditor role works). Users → the user → Generate API Keys; API keys must be allowed under Settings → Configuration → Security → Allow API Keys. Nessus: My Account → API Keys.
  2. The keys are kept in this browser profile only when "Remember" is ticked; otherwise the secret stays until the tab is closed. The tool sends them only to the endpoint you entered.

Certificate

  1. A page cannot ask you to accept a certificate. If the endpoint uses a self-signed certificate, open it once in a new tab (link next to the buttons), accept the warning or import the internal CA, then retry.

If the connection is blocked

  1. A page may only read another server's answers when that server allows it (the Access-Control-Allow-Origin header). Security Center and Nessus do not send it by default, so the browser reports a plain network failure even though the server is reachable; "Check connection" tells you when this is the case.
  2. Simplest: serve this file from the Tenable server itself, same origin, nothing to allow: copy Tenable_Pull.html (and the Studio) into the Security Center web root (the DocumentRoot named in /opt/sc/support/conf/*.conf) and open https://<security-center>/Tenable_Pull.html.
  3. Or allow this page on the Tenable side (Security Center Apache configuration): Header always set Access-Control-Allow-Origin "null" for a file opened from a folder (or the origin that serves it), Header always set Access-Control-Allow-Headers "X-APIKey, Content-Type, Accept", Header always set Access-Control-Allow-Methods "GET, POST, DELETE, OPTIONS", Header always set Access-Control-Expose-Headers "Retry-After", and answer OPTIONS with 204. Nessus has no such setting.
  4. Or a dedicated browser profile without web security, for this tool only: a shortcut such as chrome.exe --user-data-dir="%LOCALAPPDATA%\TenablePull" --disable-web-security. Never browse anything else in that profile.

Load on Security Center

  1. Every page of the vulnerability analysis is a database query. The tool sends one request at a time, waits between requests (pacing: Gentle 2 s, Normal 0.75 s, Fast 0.15 s), uses moderate pages (Normal: 1,000 vulnerability rows, 500 compliance rows), gives a request up to 2 minutes, and when the server answers 429 or 503 it waits (the Retry-After it asks for, or 2 s, 4 s, 8 s…) before trying again. The result shows the number of requests and the time the server spent.
  2. Run the pull outside the scan windows; a pull of the current estate (about 6,000 vulnerability rows and 33,000 compliance rows) is roughly 75 requests.
