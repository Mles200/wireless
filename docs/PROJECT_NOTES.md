# Tenable Report Studio (ALTANFEETHI)

Single-file browser tool (`ALTANFEETHI_Tenable_Report_Studio.html`, ~4.0 MB, version 4.6, 31 Oct 2026) that turns Security Center CSV/Excel exports into the weekly VA + CIS compliance report: Excel workbooks (one for hosts, one for network devices), PDF (generated in the browser and downloaded directly, A4, named automatically; no print dialog), a self-contained HTML report the team can browse host by host, an Archive button that saves everything in a named folder, a Validate fixes button (29 Oct: old export against new, marked list) and a Risk tab (30–31 Oct: risk-based tracker with an editable formula and a persistent register). Runs offline; nothing leaves the browser.

## Exports to take from Security Center (Analysis > Vulnerabilities > Vulnerability Detail List > Export)
- VA export: Source Cumulative, all repositories, severities Critical to Low. Keep the default filter that excludes accepted-risk findings, so risk acceptances made in Tenable drop out of the report automatically.
- Compliance export: Vulnerability Type = Compliance, severities Info + Medium + High (Info = passed checks, needed for the pass rate).
- Display Columns to tick in addition to the defaults: VPR, EPSS, See Also, CPE, Exploit Frameworks, Security End of Life Date, Family, NetBIOS. Every export column is carried into the Excel (Description, Version, Vuln Publication Date, Cross References, Host ID, Agent ID, Check Type, Accept/Recast Risk Comment included). "Steps to Remediate" is the column shown everywhere as "Solution (Tenable)".
- 25 Oct exports reviewed: same 37 columns as 20 Oct, nothing new or missing; VA 5,776 rows / 116 hosts (170 rows more than the 20 Oct export, same scan date, 4 rows with no plugin output in Tenable itself); compliance identical to 20 Oct (33,280 rows). Two exports with the same scan date loaded together are both treated as "now" and merged (newest file wins on duplicates): load only the latest, or mark the older one as history.
- 28 Oct: M sent the files he uses (`ATF- VA Report All hosts 3.csv`, 5,681 rows, Vulnerability Repository only, 127 hosts; `ATF- Compliance Report All hosts (5).csv`, 113 MB, Compliance Repository incl. the agent policy's VA rows). Loaded together the Studio has 6,368 findings / 145 hosts after 1,770 duplicates (findings held in both repositories) are removed; the export date of the compliance file resolves to 2026-10-26, so the report is dated 26 Oct.
- Any number of files can be loaded together, old and new: the newest export date is "now", older files become history for the trend and the baseline for Validate fixes (newest file wins on duplicates). A file can be switched manually (use as now / use as history).
- For a conclusive validation or risk tracking the new export must contain every host: same filters, and the Info severity included when a host may have no findings left (otherwise the host disappears from the VA export and its findings cannot be distinguished from "not scanned").

## Risk tab (v4.6, 30–31 Oct 2026)
- Why: M asked (30 Oct) for a risk factor and risk analysis to classify vulnerabilities risk-based, taking compensating controls and host exposure (internal / external) into account so the SLA can follow the risk: "if it's critical in Tenable this doesn't mean it's critical really, if it's internal and there are a lot of security controls in place". Clarified as "simply a risk-based tracker": track vulnerabilities and their risk rating and what got closed versus not, a new tab plus an Excel, no remediation workflow, identifiers host name, IP ("very critical"), vulnerability name, plugin ID. On 31 Oct he rejected the first fixed model ("needs to be adjusted a lot, or give me a way to edit the formula"), asked for a compensating-controls part where he puts the score of each control and the result is the residual risk after the controls, with the control adjustment in Risk settings, and stated the target: nothing Critical, everything Medium, maybe some High. The model was rebuilt as inherent → controls → residual with every number editable, and the defaults calibrated on his 25 Oct data to that target.
- Model (settings.risk, v2, carried by settings.json; Risk settings dialog edits every value): per finding (plugin on host). Likelihood 1 to 5 = start 1 + KEV 3 + public exploit 2 + EPSS ≥ 30% 1 + VPR ≥ 7 1 + reachable over the network (CVSS AV:N or no vector) 1 + internet-facing host 1, capped at 5. Impact 1 to 5 = host criticality from rules (1 to 5; first match wins; `environment: X`, `system: X`, `site: X`, `/regex/i`, CIDR, `internal`, `internet-facing`, `*`) adjusted by Tenable severity (Critical +1, High 0, Medium −1, Low −2), kept 1 to 5. Inherent score = L × I (1 to 25); level thresholds Critical ≥ 16, High ≥ 10, Medium ≥ 4, else Low. Compensating controls: each has a score (% of the inherent risk it removes), the kinds it covers (network, web, client, local) and where it applies (same match terms); the applicable controls combine multiplicatively (1 − Π(1 − score)) with the combined reduction capped (default 60%). Residual score = inherent × (1 − reduction), rounded to 0.1, same thresholds; KEV floor never below High (options always Critical / none); per-vulnerability override replaces the level and is recorded with reason and date. The residual level picks the remediation timeline row; risk due date = first seen + that timeline. Tenable severity and its due date stay visible; the weekly report is not changed.
- Default criticality rules: Active Directory, ADFS, Database, CRM, Hayaak 4; Web Application Proxy 3; environments Production, DR, Network, CCTV 3; HQ, Pre-Production 2; everything else 2 (5 kept free for him). Default controls and scores: Cortex XDR agent on servers 40% (client, local; Production, DR, Pre-Production, CCTV); FortiGate zone segmentation and IPS 40% (network; internal); WAF in front of the public applications 40% (web; internet-facing); Netskope ZTNA (internal applications not published) 20% (web; internal); NAC (ClearPass) on HQ and terminal LANs 20% (network; HQ). Kinds of vulnerability: web (CGI/Web Servers families, TLS/SSL theme, web server names), client (browsers, Office, Adobe, archivers, Java client), local (AV not N), network (AV:N and not client, or no vector).
- Result on the 25 Oct data with the defaults (6,368 open findings, no internet-facing host configured): residual Critical 0, High 1,577 (mostly the KEV floor), Medium 3,152, Low 1,639; inherent before controls: Critical 1,171, High 2,147, Medium 2,693, Low 357. 5,089 findings end below the Tenable severity, 15 above. Calibration was done by simulating weights, thresholds and control scores on the export (`work` simulation, 31 Oct); the knobs that move the Critical count are the two 40% scores and the Critical threshold.
- Register (IndexedDB key `riskRegister`, exportable as `risk-register.json`, restored by dropping the file on the Studio, included in the archive): one item per plugin|ip ever seen with first seen, last seen, status Open/Closed, closed date (= export date when the finding is no longer reported while the host is still in the export), reopened count, the last computed inherent/residual values and controls, plus the per-vulnerability overrides (level, note, date). Synced on every rebuild; an export older than the register's last export changes nothing and the tab shows a notice. Items still Open on hosts absent from the current export are shown as Open with "In export: No, last seen <date>" and counted separately ("more open on hosts not in this export").
- Tab (Studio only, hidden in the HTML report; the scope bar applies): KPIs (open findings, residual by level with the inherent count underneath, rated below/above Tenable, closed, overrides); filters by residual level, Open/Closed/both, exposure, re-rating (below/above/overridden), search (host, IP, plugin ID, name, CVE); one row per vulnerability (residual = highest open, inherent, Tenable severity, plugin ID, factors, hosts open/closed, hosts by residual level, override drop-down with a reason prompt); expand for the per-host rows (status, residual, host, IP, environment, exposure, in export, criticality, L, I, inherent score and level, controls with scores, reduction %, residual score, factors with points, first seen, risk due date, closed on). Buttons: Risk settings, Excel.
- Risk settings dialog: likelihood points (start, KEV, exploit, EPSS points and threshold, VPR points and threshold, network, internet-facing), impact adjustment per Tenable severity, level thresholds, KEV floor, criticality rules textarea (1 to 5), controls table (name, covers checkboxes, applies-to text, score %, remove) with Add control, cap on the combined reduction, Reset to defaults, Export register, Clear register, Apply. Settings older than v2 are replaced by the defaults on load.
- Excel `<org>_Tenable_Risk_Tracker_<date>.xlsx`: Summary (residual vs Tenable cross-tab, inherent vs residual cross-tab, by environment, exposure, controls with the findings they apply to, tracking figures, sheet index) · Risk tracker (one row per finding: Status, In current export, Residual risk, Inherent risk, Tenable severity, Host, IP, Plugin ID, Vulnerability, CVE, Environment, System, Exposure, criticality, likelihood, impact, inherent score, controls applied with scores, reduction, residual score, factors with points, override and note, first/last seen, closed on, risk due date, Tenable due date, overdue) · By vulnerability · Model (the formula with the values in force, rules and controls). Archive: checkbox "Risk tracker (Excel and risk-register.json)".
- Procedure note given to M: the SVA procedure (ATF-SMO-CC-PP-L3-SVA) needs one clause saying timelines follow the residual risk level after a documented re-rating with compensating controls, recorded in the register; otherwise the adjusted dates read as SLA breaches to an auditor. Tenable's own Recast Risk remains the place when the severity in Security Center itself should change.

## How numbers are counted
- A finding = one vulnerability on one host (plugin + host + port + protocol). The same finding stored in two repositories (host scanned by agent and by the network scanner) is counted once. Tenable's Findings page counts per repository, so its totals are higher; the Dashboard "Data check" panel and the Excel Summary "Reconciliation with Tenable" block show the per-repository counts and the duplicates removed.
- Informational rows (severity Info, non-compliance plugins) are inventory only: they give OS identification (plugin 11936) and host names, never findings; any host with an Info row is a "scanned" host and appears in the Hosts register with the status "No findings". Coverage figures stay in the tool and the Excel, not in the PDF.
- Identifiers: Tenable plugin IDs only, exactly as in the export (no invented references).
- Priority: P1 = CISA KEV or VPR 9+; P2 = public exploit, EPSS 30%+ or VPR 7+; P3 = other Critical/High; P4 = Medium/Low. Due dates = first discovered + timeline (Critical 5/14 days, High 20/30, Medium 40/60, Low 90/90 for internet-facing/internal; KEV uses the Critical timeline).
- A remediation action = one product or update family with the Tenable solution text and the complete host list; ordered by severity then hosts affected.
- CIS checks: the plugin output is parsed for Result, Actual Value, Policy Value, Information, Solution (the audit's remediation, e.g. the GPO path), Impact, See Also and Reference Information (framework mappings); the Solution shows in the tool, the printable report, the PDF failed-checks table and the Excel.
- Environments come from the segmentation rules (Settings): hostname rules first, then subnets. Only real zones are used as environments (Production, DR, Pre-Production, CCTV, HQ, Network); no tool-specific categories. M's ruling 20 Oct: the Tenable scanner (PRD-TNB-SCAN-01) and 10.70.30.0/24 are Production; Linux vs Windows is the OS dimension, not an environment. "Tenable" remains only as the System label of the scanner. The Network environment is 10.70.100.0/24 and 10.70.200.0/24 (FortiGate hub) and 192.168.10.0/24 (the firewall loopbacks); CCTV cameras and recorders (172.20.0.0/16) are CCTV, not Network; hosts named *cctv* (the CCTV AD/WSUS/jump servers in 10.80.81.0/24) are CCTV by the hostname rule.

## Excel workbook (ExcelJS)
- Sheets in order of importance, each with a tab colour, a guidance line in row 1, a dark header row with notes (comments) on key columns, frozen header, autofilter, coloured Severity and Result cells, red "Overdue" status, dates as real dates, thousands separators: Summary (copper: figures, results by environment, categories, reconciliation with Tenable, index of sheets with links) · How to read (copper) · Remediation actions (red) · Priority vulnerabilities (red) · VA evidence by host (orange: one row per finding, Evidence = Tenable plugin output in column K, Solution, Synopsis, Description and every export column) · VA consolidated (orange) · CIS failed checks (blue: expected value, Solution from the audit, failing hosts, description, impact, framework references) · CIS evidence by host (blue: every check per host, Result coloured, "filter Result to Failed" guidance, expected and actual values, solution) · Hosts (grey: register of every host incl. no-findings ones, counts, CIS results, risk score, top 5 actions) · Source VA export / Source compliance export (grey, last: the original Tenable export rows unchanged, all 37 columns, re-read from the loaded file when the Excel is built; off via Settings "Include the original export rows"; not available in the HTML report's Excel since it has no source files).
- Cells are capped at 32,000 characters (Excel's limit is 32,767; some Tenable plugin outputs such as installed-software enumeration exceed 240 KB) with a note pointing to the source export.
- Built with ExcelJS 4.4.0 (bare build, +0.9 MB in the tool) because SheetJS Community cannot write styles; SheetJS stays for reading xlsx/xls inputs. ~11 MB for the hosts workbook with the source sheets (3.5 MB without) in ~25 s for the 25 Oct data; the network workbook is seconds.
- **26 Oct repair prompt, fixed.** Excel opened the 25 Oct workbook with "We found a problem with some content … Repaired Records: View from /xl/worksheets/sheet2.xml". Cause: the How to read sheet was given a frozen pane with a zero split (`state:'frozen', ySplit:0`), which ExcelJS writes as `<pane state="frozen">` without a split; Excel rejects a frozen pane that freezes nothing. The sheet now has a plain view (gridlines off), every data sheet keeps its `ySplit` of 1 or 2. Every cell value also goes through one sanitiser (`xs`): XML control characters removed, text capped, NaN/Infinity and invalid dates dropped, so the other known causes of the same prompt cannot occur. openpyxl and LibreOffice open such files without complaint, which is why the QA did not catch it; `test/xlsx_strict.py` now inspects the XML parts the way Excel does (frozen panes, well-formedness, control characters, NaN values, text length, overlapping merges, hyperlink relationships, sheet names, widths/heights, ranges) and reproduces Excel's finding on the old file and nothing on the new one.

## Archive (v4.4, 25 Oct 2026)
- Archive button (Studio only, after exports are loaded): asks for a folder name (default "<period> scan <date>", e.g. "Q4 2026 scan 2026-10-25"; Windows-invalid characters are replaced) and which outputs to include, then generates and saves: `Source exports/` (the loaded files as uploaded, history files prefixed "history "), the PDF, the Excel workbooks (hosts and network), the HTML report, the validation workbook when a history file is loaded and the risk tracker with `risk-register.json` (v4.6), `summary.txt` (scope, counts, source files, file list, how to regenerate), `settings.json` (report settings and rules incl. the risk model; dropping it on the Studio restores them) and `Tenable Report Studio/` (a copy of the tool version that produced the run).
- Folder handling (Chrome/Edge, File System Access API): a browser page cannot write to disk silently and cannot write next to its own file without permission, so the parent folder is chosen once; the picker opens in the well-known folder where the tool file lives (Desktop, Downloads or Documents, read from the file:// path) and the picker's `id` makes Chrome reopen at the last place. The handle is kept in IndexedDB, so later archives show "Save to <folder>" and need at most a one-click permission confirm (Chrome's "allow on every visit" removes even that); "Change folder" picks another parent. An existing folder with the same name is never overwritten (suffix " (2)"). "Download ZIP" is the fallback for other browsers or blocked policies; the ZIP holds the same folder (deflated with CompressionStream; a minimal ZIP writer is built into the tool, no library).
- M asked (25 Oct) for saving next to the tool without choosing: answered that it is not possible from a browser page; the remembered-folder design above is the closest.

## PDF (v4.3): generated with pdfmake, official register
- Built in the browser from the same data as the HTML report (pdfmake 0.2.20 + IBM Plex Sans/Mono subset embedded in the tool; Arabic organisation name rendered through a canvas image on the cover). ~0.8 MB, A4, page footer "ALTANFEETHI · title · period | classification · Page x of y", PDF metadata title/author set. The Report tab stays as the on-screen preview (Ctrl+P still prints it).
- Structure: 1 Introduction (purpose, scope table, remediation timelines centred, methodology and definitions) · 2 Executive summary (figures, summary of results, severity chart) · 3 Findings overview (results by environment incl. total row, charts) · 4 Remediation actions (top N detailed with solution and every host, then all remaining actions with their hosts) · 5 Priority vulnerabilities (top N detailed with every host) · 6 Host risk ranking (all hosts) · one chapter per environment (figures, summary, top 10 actions, 8 most widespread vulnerabilities, all hosts) · Configuration compliance (CIS benchmarks; failed-checks table shows expected value and the audit's solution) · Trend and ageing (comparison table with the previous export) · optional appendices (registers).
- No "how to read", no "fix first", no "N more hosts in Excel" notes; every host table is complete. N (detailed rows per section) is a setting, default 25.
- pdfmake rules learned: no zebra row fill in tables that contain nested label tables (the row fill paints over them); long unbreakable tokens (registry paths, URLs) get soft breaks or the column overflows the page; footer nodes count as "following nodes" in pageBreakBefore, so they are filtered out when keeping headings with their content.
